# Terminal Client Implementation Plan

> Historical design/development record. Later changes may supersede the original
> scope, limits and verification counts. See the [current documentation](../../README.md)
> for supported commands and behavior.

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Let humans play existing server games in a full-screen terminal.

**Architecture:** A synchronous session wraps SchottenClient and rules-based claims.
A curses interface schedules its network operations on one background worker.

**Tech Stack:** Python, curses, concurrent.futures, existing httpx client, pytest.

**Spec:** docs/superpowers/specs/2026-11-16-terminal-design.md

## Global Constraints

- No new dependencies or server changes.
- All network work runs outside the curses event loop.
- Display stone indices as 1–9; API uses 0–8.
- Never automatically retry uncertain writes.

## Review Focus

- Waiting/opponent turns must not request legal moves.
- Claims enabled by the selected card must be included.
- Passing must be refused when a legal play exists.
- Failed requests must leave the interface usable.
- Small terminals and no-color terminals must render safely.
