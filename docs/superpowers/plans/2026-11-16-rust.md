# Rust Implementation Plan

> Historical design/development record. Later changes may supersede the original
> scope, limits and verification counts. See the [current documentation](../../README.md)
> for supported commands and behavior.

> **For agentic workers:** Use superpowers:executing-plans or bounded parallel implementation.

**Goal:** Native game engine, compatible REST server and fast native bot series.
**Architecture:** One Rust crate with rules/engine, bots, Axum server and CLI.
**Tech Stack:** Rust stable, serde, Axum/Tokio, clap, rayon; Python parity tests.
**Spec:** docs/superpowers/specs/2026-11-16-rust-design.md

## Global Constraints

- Preserve existing Python source and REST contract.
- Integer-seeded decks match Python; bots receive visible state only.
- Optimize for native ARM64; measure correctness and performance separately.
- No commits or new branches. Work in place because the reference is untracked.

## Review Focus

- Invalid JSON/indices/cards must return INVALID_REQUEST rather than panic.
- Claims must not consult opponent hidden cards.
- Long-poll/SSE must not miss state changes or hold game locks while waiting.
- Native parallel runs must be deterministic with explicit seeds.
- Comparisons must distinguish engine, HTTP, and client overhead.

## Verification ledger

- Native compiler: Rust 1.100.0, aarch64-apple-darwin, native CPU apple-m4.
- Current workspace retained: all original source was untracked and would not
  have appeared in a separate worktree. No commits or branch changes.
- Formation comparison covers all 24,804 combinations, including independent
  Python checksum of formation and total bytes (0xebf803366e80f211).
- 27 Rust tests pass, including Python MT19937 and full trace fixtures.
- 137 Python tests pass; 123 external tests skip without a server URL.
- All 123 external differential tests pass against live optimized Rust server.
- rustfmt and Clippy with warnings denied pass.
- Independent server review found validation and shutdown issues; all reproduced
  by regressions and fixed. A second independent core review found no substantive
  actionable issues in rules, RNG, engine or bots.
- HTTP harness corrections: game IDs are opaque, HTTPX disallows trailing spaces
  in outgoing authorization headers, and deadline assertions allow the documented
  millisecond resolution. None changes game outcome comparisons.
- Benchmarking uses sequential external-wall-clock measurements, separating native
  simulations from Python clients over HTTP; native simulation omits event history.
