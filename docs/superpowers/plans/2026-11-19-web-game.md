# Browser Game Implementation Plan

> Historical design/development record. Later changes may supersede the original
> scope, limits and verification counts. See the [current documentation](../../README.md)
> for supported commands and behavior.

> **For agentic workers:** Execute the independent UI and replay tasks in parallel;
> the primary agent implements bot sessions and integrates/tests the result.

**Goal:** Play against native MCB and watch saved tournaments in an attractive local web UI.
**Architecture:** Embedded HTML/CSS/JS, web-specific Axum routes, native bot sessions,
validated recording snapshots reconstructed by the authoritative engine.
**Tech Stack:** Existing Rust/Axum/Tokio, buildless browser JavaScript.
**Spec:** docs/superpowers/specs/2026-11-19-web-game-design.md

## Constraints

- Work in place: the source is untracked and cannot be reproduced in a worktree.
- No commits, branches, hosting, new runtime dependencies, or changes to existing REST behavior.
- Real MCB, samples 1–100 (default 20), private bot hand, blocking search off async threads.
- Configurable recordings root; paths cannot escape it, including via symlinks.

## Review focus

- Duplicate turns or disconnected requests must not cause duplicate/lost bot moves.
- A replay must validate its deal, turns and final outcome, including wide seeds.
- Token errors and malformed inputs must not expose private hands or crash.
- Reload, switching modes and slow responses must preserve active-game correctness.
- Narrow screens, keyboard operation, empty libraries and errors must remain usable.

## Interfaces

- `web::router(recordings: PathBuf) -> Router`: merges bot and recordings routers;
  serves `/`, `/web/app.js`, `/web/style.css` from embedded assets.
- `POST /web/games`: `{samples?:20,seed?:i64,bot_seed?:i64}` -> seat grant.
- `GET /web/games/{id}`: bearer auth -> standard seat-0 view plus
  `bot_thinking:bool`, `bot_error:string|null`.
- `POST /web/games/{id}/turn`: bearer auth, standard TurnRequest; computes
  provable human claims server-side after chosen play; returns same enriched view.
- `recordings::router(root: PathBuf) -> Router`:
  `GET /web/recordings` -> `{games:[{id,game_id,seats,winner,reason,turns}],warnings:[string]}`.
  `id` is `run-directory/game-file.json`.
  `GET /web/recordings/{run}/{file}` -> `{metadata:{game_id,seats,winner,reason,turns},frames:[...]}`.
  Each frame is standard seat-0 GameView plus `opponent_hand` and `last_turn`
  (null initially, otherwise recorded LogEntry). Frames include the joined initial
  position and every accepted recorded turn.

## Execution record

Approved design; user instructed implementation with “go ahead”. No second
approval gate. Keep existing untracked source intact; perform bounded parallel
work only in separate owned files. Web routes use a separate contract so the
Python/shared game contract remains unchanged.
